# Отчёт по проекту Training Analytics

## Суть приложения

**Training Analytics** — веб-приложение для учёта и анализа персональных тренировок. Пользователь может регистрироваться и входить в систему, добавлять тренировки (силовые и на выносливость) с датой и параметрами, просматривать список по дням и строить аналитику: столбчатые графики по датам (объём, повторения, километры, минуты) и круговые диаграммы по типам нагрузок. Данные запрашиваются с бэкенда по API; состояние авторизации и частично данные хранятся на клиенте через Redux. Ключевая техническая идея проекта — использование **Apache ECharts** для визуализации и **date-fns** для надёжной работы с датами (календарь, группировки по неделям/месяцам, локализованный вывод).

## Технологии

### Redux Toolkit

Redux Toolkit — официальный набор утилит для Redux: упрощённая настройка стора, слайсы с `createSlice`, встроенный Immer для иммутабельных обновлений. В проекте используется для глобального состояния: авторизация (пользователь, токен, ошибки), а данные тренировок частично дублируются в сторе при загрузке страниц. Выбор обусловлен необходимостью единого источника правды для авторизации и предсказуемой работы с асинхронными действиями. Альтернативы вроде Zustand или Jotai проще в настройке, но Redux Toolkit даёт привычную модель actions/reducers и удобные devtools; для контекста только авторизации можно было бы обойтись React Context, но при росте приложения Redux масштабируется лучше.

### React Router

React Router — библиотека маршрутизации для React. В проекте заданы маршруты: `/login`, `/register`, `/` (дашборд), `/trainingList`, `/data-entry`, `/analytics`, `/analytics/:date`. Используются защищённые маршруты (редирект неавторизованных на логин) и навигация по ссылкам. Выбор обусловлен стандартностью решения для React SPA и поддержкой вложенных маршрутов и параметров. Альтернативы (TanStack Router, Next.js App Router) уместны при SSR или более сложной маршрутизации; для данного SPA React Router достаточен.

### Material UI (MUI)

Material UI — набор React-компонентов в стиле Material Design (кнопки, поля ввода, карточки, типы, иконки и т.д.). В проекте MUI используется для форм входа и регистрации, кнопок и ссылок на дашборде, карточек и списков на страницах тренировок и аналитики, переключателей периода (неделя/месяц). Выбор сделан ради быстрой сборки единообразного UI без написания своих компонентов с нуля. По сравнению с Ant Design или Chakra UI MUI даёт очень богатый набор компонентов и тем; недостаток — размер бандла и необходимость Emotion (уже включён в зависимости).

### Apache ECharts и echarts-for-react

**ECharts** — библиотека для построения интерактивных графиков (столбчатые, линейные, круговые, комбинированные и др.) с гибкой настройкой осей, подсказок и легенд. **echarts-for-react** — тонкая обёртка, которая прокидывает конфигурацию ECharts в React-компонент и управляет жизненным циклом инстанса. В проекте ECharts — основа визуализации: столбчатые графики по датам (одна или две серии, например вес и повторения) на странице аналитики и круговые/кольцевые/«роза» диаграммы на странице списка тренировок для отображения соотношения силовых и кардио. Выбор обусловлен мощными возможностями без тяжёлой кастомизации: две оси Y, поворот подписей, тултипы из коробки. По сравнению с Chart.js ECharts лучше подходит для сложных и комбинированных графиков и богатой интерактивности; по сравнению с D3.js — быстрее внедрить без низкоуровневого кода. Таким образом, ECharts — одна из двух центральных технологий проекта наряду с date-fns.

### date-fns

**date-fns** — библиотека для работы с датами в JavaScript: форматирование, интервалы, начало/конец периода, проверки (сегодня, будущее), локали. В проекте используется прежде всего на странице ввода данных: календарь месяца строится через `startOfMonth`, `endOfMonth`, `startOfWeek`, `endOfWeek`, `eachDayOfInterval`, навигация по месяцам — через `addMonths`/`subMonths`, отображение выбранной даты и заголовка месяца — через `format` с локалью `ru`. Также даты участвуют в подготовке данных для аналитики (группировки по неделям и месяцам) и в единообразном формате при отправке на API (`yyyy-MM-dd`). Выбор обусловлен модульностью (импорт только нужных функций), иммутабельностью и встроенной поддержкой локалей. В сравнении с Moment.js date-fns легче и не мутирует объекты дат; по сравнению с нативным `Intl` и ручной арифметикой дат — проще и безопаснее для календарной логики. Наряду с ECharts date-fns образует вторую опору проекта: вся работа с датами и календарём строится на ней.

### Axios

Axios — HTTP-клиент с поддержкой промисов, перехватчиков и отмены запросов. В проекте используется для вызовов API авторизации и тренировок (логин, регистрация, получение и создание записей). Выбор обусловлен удобным API, единой обработкой ошибок и возможностью задать базовый URL и заголовки (в т.ч. Bearer) в одном месте. По сравнению с `fetch` Axios даёт более короткий код и интерцепторы; для простого SPA без сложной логики запросов альтернативы вроде React Query не обязательны, поэтому Axios здесь уместен.


## Заключение

Проект задуман как практическое применение двух технологий: **Apache ECharts** для графиков и **date-fns** для дат. ECharts оправдал ожидания: столбчатые графики с двумя осями и круговые/кольцевые диаграммы настраиваются через конфиг без тяжёлого кода, а echarts-for-react органично вписывается в React. date-fns оказался удобным для календаря выбора даты и для всех операций «начало/конец периода» и форматирования; русская локаль упростила вывод дат пользователю. Остальной стек (React, TypeScript, Redux Toolkit, MUI, React Router, Axios, CRA) выбран под задачу быстрой разработки SPA с авторизацией, формами и аналитикой без избыточной сложности.

Итоговая суть проекта — не только учёт тренировок, но и демонстрация связки **ECharts + date-fns**: первая даёт наглядную аналитику по времени и типам нагрузок, вторая — корректную и читаемую работу с датами в календаре и в отчётах. Обе библиотеки хорошо сочетаются с React и позволяют в дальнейшем расширять отчёты (новые типы графиков, экспорт, фильтры по периодам) без смены технологий.
